# DeepSeek 分批论文请求超时与恢复 — 2026-10-21

## 已确认原因

截图对应项目 `[运行/项目 ID 已省略]`、运行 `[运行/项目 ID 已省略]`。运行记录显示 `paper_drafting` 已合并前两批，第三批 DeepSeek 请求累计约 30 分钟后触发旧版请求超时，工作流因此暂停。

旧版本只在内存中合并成功批次，没有逐批保存论文草稿。暂停后恢复会重新请求整段论文，无法复用已经完成的分章。该旧运行目录没有可用于恢复的分章检查点，因此无法从新版本中还原旧运行已丢失的两批文本。

## 修复

- DeepSeek 单次生成请求等待上限由 30 分钟提高到 60 分钟；没有在超时后自动重试，避免未经用户再次操作就产生额外请求和费用。
- 每个成功分章在通过校验后，写入当前运行目录的原子检查点。检查点绑定项目、运行、阶段尝试和请求输入指纹，并校验响应哈希；不匹配或损坏的检查点不会复用。
- 用户从新版本继续同一轮时，会复用已通过完整候选 Word 草稿校验的批次，并从第一个未完成批次继续请求。检查点写入前会校验累计内容、证据引用、模板锚点、公式和合并结果，避免无效批次让恢复流程陷入重复失败。
- 论文阶段成功结束后会清理由本阶段创建的检查点。
