# 桌面端更新:多工作表 XLSX 导入修复 — 2026-10-25(第二次部署)

## 用户报障

新建项目导入 `[本机路径已省略]` 下多个 XLSX(result1–3、result4-2/3、附件1–4)时,
界面报"创建失败:请明确选择工作表;可用工作表:计划购电量、充电电量"。

## 根因

`read_xlsx` 对包含多个工作表的工作簿 fail-closed 要求显式选择
(单表文件自动选择);后端全链路(`ProjectService.create(sheets=…)`,
`ImportService.populate(sheets=…)`,恢复运行时的
`_preserved_xlsx_sheets`)早已支持按文件名指定工作表,
但**新建项目向导从未收集工作表选择**——UI 与后端能力脱节,
导致所有多表 XLSX 一律无法导入。

## 修复

- `inputs/xlsx_reader.py`:新增 `xlsx_sheet_names()`,
  与 `read_xlsx` 共用同一套 ZIP/XML 安全预检
  (defusedxml、加密/外部链接/宏拒绝、大小与结构上限),
  只读返回工作表名,供 UI 建立选择项。
- `ui/project_wizard.py`:
  - 选中 XLSX 时即探测工作表名并缓存(按文件名索引;
    向导本就禁止同名文件,与后端 sheets 的文件名键一致);
  - 多表 XLSX 在文件列表行内显示"工作表"下拉框,
    默认选第一个工作表,切换即时生效;单表 XLSX 不显示下拉框;
  - XLSX 解析失败(如损坏文件)时导入整体 fail-closed 并提示,
    不启动后台任务;
  - "创建项目并导入"把 `{文件名: 工作表}` 传入
    `ProjectService.create(sheets=…)`;
  - 移除文件时同步清理该文件的工作表缓存与选择。
- 已知边界:每个多表 XLSX 导入为一个数据源,
  工作表选择决定数据画像与后续计算输入;未选择的表不导入。
