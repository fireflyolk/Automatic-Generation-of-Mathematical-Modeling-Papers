# B078 长文论文与结构化图示扩展实施计划

**Execution:** Native 本会话；按用户“那你修改”的明确要求实施。

## 约束

- 只使用 `[本机路径已省略]` 作为源码区，构建和临时文件分别位于新的 F 盘任务子目录。
- 保留当前工作树的所有既有修改，不提交、不推送，不操作运行中的 C 盘应用及 Word 文档。
- 不运行或新增自动化测试；最终只报告实际完成的源码、构建、启动检查和未覆盖证据。
- 不改写用户的 `[本机路径已省略]`。

## 任务

1. 扩展规范档案至 1.1.0，默认 45 页、目标范围 40–50 页，保留 1.0.0 规范档案的校验读取能力。
2. 将论文请求拆为最多八段；增加每段进度提示、结构校验和结果合并。合并完成前不写论文产物。
3. 新增安全的本地流程图渲染模块，并在 Word writer 中支持多个章节内插图、连续图号、说明文字和图示元数据。
4. 扩展 `paper-manifest.json` 与 DOCX QA 的篇幅、公式、流程图统计和非阻断型质量建议。
5. 在运行授权页披露最多八个分章、每段一次格式纠正重试（最多十六次请求）及 DeepSeek 实际 token 用量；读取模型目录的单次输出上限，应用截顶至 16,384 tokens。
6. 更新现有 release 文档结构中的本次验收记录，在新的 F 盘目录执行冻结包构建与启动检查；不运行 pytest，不声称 Word 页面或真实 Agent 验收通过。

## 验收检查

- 变更限于论文规范、分章生成、Word 写入/QA、DeepSeek 输出上限适配与授权披露、构建所需的 F 盘 runtime 入口，以及本次验收记录。
- 标准 ID/版本/hash 在新清单内一致；旧 1.0.0 manifest 可由 QA 解析。
- 流程图协议不会执行输入内容或载入外部图像；图示仅从已校验的节点和连线本地生成。
- 质量建议不改变已有硬性暂停条件。
- 构建目录、缓存目录和启动检查数据目录均位于 F 盘；未覆盖项明确列出。
- 计算 runtime 与当前 Sandbox 入口协议一致；构建和启动检查不修改旧 runtime、C 盘安装或快捷方式。
