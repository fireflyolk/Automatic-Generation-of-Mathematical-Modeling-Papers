## 1. 产品目标

开发一个面向个人数学建模竞赛/研究的 Windows 桌面工作台。用户粘贴题目、导入 Excel/CSV 和 Word 模板后，软件调用本机已配置的 Agent CLI，自动完成数据检查、模型构建、代码计算、结果核验和论文初稿生成。最终产物可编辑、可复算、可追溯。

软件生成的是可审阅的论文草稿，不保证数学结论正确，也不自动投稿或上传论文。

## 2. 已确认的用户决策

| 主题 | 决策 |
|---|---|
| 使用对象 | 个人 Windows 单机 |
| 桌面框架 | PySide6 原生桌面 |
| Agent 接入 | 复用本机 CLI 登录；首版支持 Codex 和 Claude Code CLI |
| 输入 | 粘贴题目，导入 Excel/CSV |
| 输出 | 可编辑 Word，支持导入并保留自定义 DOCX 模板 |
| 自动化 | 用户启动后尽量自动完成整条流程；在关键阻塞时暂停 |
| 数据外发 | 允许发送给用户选择的服务商；运行前显示服务商与项目文件范围 |
| 存储 | 项目、应用数据、临时文件、日志、缓存和生成物使用 F 盘 |
| 非目标 | 首版不做团队/局域网协作、云端存储、自动投稿 |

## 3. 核心使用流程

1. 新建项目，粘贴赛题正文，选择 Excel/CSV 数据文件和 DOCX 模板。
2. 导入时保留源文件副本并生成文件摘要；原始文件不被修改。
3. Agent 检查数据字段、类型、缺失值、异常值和基本统计特征，并生成数据说明。
4. Agent 提取题目目标、子问题、约束、变量与评价指标，记录不确定项。
5. Agent 给出模型假设和候选方案，说明选择依据；题意关键歧义或数据缺失时暂停并询问用户。
6. Agent 生成代码并运行计算，保存脚本、日志、结果表和图表。
7. 验证阶段检查计算是否成功、输出是否完整、数值是否有效，并对关键结果执行合理性/敏感性检查；失败时允许有限次数修复，持续失败则暂停。
8. Agent 根据模型、结果和模板撰写论文草稿。每个主要结论关联到模型产物或计算结果；没有来源的参考文献作为待补项标记，不虚构引用。
9. 软件把 DOCX 写入新的输出文件，保留模板原文件，并提供预览和交付目录。

自动运行不是无人监管：用户点击开始后，各阶段自动衔接，不要求逐阶段确认；出现阻塞、越权路径、连续验证失败或 CLI 未就绪时暂停。用户可以随时停止，并从最近的阶段检查点恢复。

## 4. 功能范围

### 4.1 项目管理

- 每个赛题对应独立项目目录。
- 展示项目阶段、Agent、运行状态、最近错误和输出文件。
- 保存阶段产物、Agent 运行记录、检查点与恢复信息。
- 可从中断阶段继续运行；已完成产物不被静默覆盖。

### 4.2 数据检查

- 首版接受 CSV 和常见 XLSX 文件。
- 对源数据做只读检查；清洗结果另存为新文件。
- 记录列名、类型、缺失值、异常值和用于计算的转换规则。
- 对大表、公式单元格、合并单元格或无法可靠解析的文件给出明确提示。

### 4.3 Agent 编排

- 统一 AgentAdapter 接口提供可用性检测、版本检测、登录状态的非敏感摘要、流式输出、运行取消、能力声明和错误归类。
- 首版适配器为 Codex CLI 与 Claude Code CLI；具体子进程协议按实现时的受支持版本核实并固定。
- 任务按题意分析、数据分析、建模、编码、验证、论文撰写顺序执行。可使用另一个可用 Agent 做独立审阅，但不得把审阅结果包装成数学正确性的证明。
- 应用不保存、导出或复制 provider 凭据；由各 CLI 自己处理认证。
- 运行开始前显示所选服务商、工作目录以及 Agent 可访问的项目文件范围。用户可修改范围或取消。
- 显示提示词和工作区文件可能被所选服务商处理。应用不声称项目数据只留在本机。

### 4.4 代码执行与权限

- 所有项目输出写入当前 F 盘项目目录；临时目录、日志和缓存也配置在 F 盘。
- Agent 的工作目录固定为当前项目；拒绝访问项目外路径的操作。
- Agent CLI 必须能提供受限工作区权限。若适配器无法确认或施加足够的权限边界，自动运行应禁用或暂停，不能默认为全盘读写/免审批。
- 计算脚本在受控项目环境中运行，设置运行时限、资源上限和可取消能力；记录解释器、依赖、命令和退出状态。
- 原始输入和模板只读保留；新输出使用新文件名或新目录。
- 软件不启用自有遥测，不运行未经用户选择的联网检索和插件。

### 4.5 Word 论文生成

- 导入 DOCX 后先读取章节、标题样式、页面设置、表格和图表区域。
- 用户在模板映射界面确认摘要、问题重述、假设、符号说明、模型建立、求解、检验、结论、参考文献等章节位置。
- 从模板副本生成新论文；源模板不改写。
- 对模板不支持的结构、复杂文本框、嵌入对象或不明确的插入点给出提示，不默默重排页面。
- 论文段落、公式、图表和表格使用模型运行产物；缺少证据的结论或引用要标记为待审阅。
- 完成后提供页数、缺失章节、未引用图表和待补文献检查摘要。

## 5. 技术架构

- **桌面界面**：PySide6，负责项目导航、阶段进度、Agent 输出、数据摘要、模板映射、论文预览和设置。
- **应用服务**：Python 模块划分为项目管理、数据读取、工作流编排、Agent 适配、运行执行、Word 生成和检查点管理。
- **Agent 通信**：由各适配器通过本机 CLI 与应用交互；应用不建立云端中转服务。
- **项目元数据**：SQLite 保存项目索引、阶段状态、审批/运行记录引用和文件清单；实际数据、代码、结果与 DOCX 保存在项目目录。
- **文件处理**：以 DOCX 包结构为依据复制并填充模板；对原始包保留副本并做输出结构检查。
- **F 盘布局**：

  - mathmodel-paper-studio-20261015/app/logs/
  - mathmodel-paper-studio-20261015/app/cache/

  - mathmodel-paper-studio-20261015/projects/<project-id>/10_analysis/
  - mathmodel-paper-studio-20261015/projects/<project-id>/20_models/
  - mathmodel-paper-studio-20261015/projects/<project-id>/30_src/
  - mathmodel-paper-studio-20261015/projects/<project-id>/40_results/
  - mathmodel-paper-studio-20261015/projects/<project-id>/50_figures/
  - mathmodel-paper-studio-20261015/projects/<project-id>/60_paper/
  - mathmodel-paper-studio-20261015/projects/<project-id>/90_runs/
  - mathmodel-paper-studio-20261015/docs/superpowers/specs/
- **临时文件**：应用临时目录指向 [本机路径已省略]。应用不得静默把项目输入、日志、缓存或生成文件写到 C 盘。
- 各 CLI 原生安装和认证状态由其本身管理；应用不复制或修改其凭据文件。实现时需核对各 CLI 的临时目录/缓存行为，不能声称应用控制了 CLI 自身的所有文件写入。

## 6. 数据流与隐私提示

题目、选定数据、代码、运行结果和论文内容可能被 Agent CLI 读取并发送给对应服务商。开始运行前，应用需展示：

- Agent 服务商名称和 CLI 状态；
- 项目根目录及可访问文件范围；
- 本次工作流阶段和计划处理的数据；
- 可取消入口及项目数据可能外发的说明。

文件范围提示描述的是 Agent 有权读取的范围，不保证与服务商收到的精确请求载荷一一相同；具体网络请求由所选 CLI 与服务商处理。用户未选择的项目外文件不应开放给 Agent。

## 7. 非目标

- 多人协作、账号/权限体系、局域网服务和云端同步。
- 应用自有模型 API、API Key 管理、模型市场或密钥迁移。
- 自动从互联网检索并验证论文参考文献。
- 自动投稿、自动发送邮件或把成果上传到论文平台。
- 保证任意 DOCX 模板都能无映射地自动填充。
- 把 Agent 自述或代码运行成功等同于模型有效或论文结论正确。

## 8. 首版验收条件

- 可在 Windows 桌面创建项目、粘贴中文题目并导入 CSV/XLSX。
- 可导入 DOCX，映射论文章节并生成新文件；原模板和源数据不变。
- 启动前显示 provider、工作目录、文件范围与数据外发提示。
- Codex 与 Claude Code CLI 可被分别检测；一个未配置时不影响另一个。
- 自动工作流能生成数据摘要、模型说明、可运行代码、结果文件、图表和 Word 草稿。
- 关键计算步骤有日志和可追溯输入；失败时停止或恢复，不静默编造结果。
- 项目、应用数据库、临时文件、日志、缓存和输出都写到 F 盘指定目录。
- CLI 无法提供项目范围权限时，不启动自动执行。
- 论文输出是新的待审阅草稿；不自动发布或上传。

## 9. 风险与实现前置核对

1. Codex/Claude CLI 的协议、登录状态读取和沙箱选项可能随版本变化；实现计划需先以官方文档和本机安装版本核对，再固定支持范围。
2. “工作目录是项目目录”本身不构成安全沙箱；各适配器必须验证实际权限机制。不能满足时，自动模式必须暂停。
3. DOCX 模板格式差异很大；首版通过章节映射支持，不承诺对任意复杂模板无损自动填充。
4. Agent 输出的数模结论需要专业复核；应用可提供一致性和数值检查，不能证明数学推导正确。
5. 外发提示应展示可访问文件，而不是误称数据只在本机处理。
6. CLI 可能维护自己的配置或缓存目录；应用不能在未经用户许可时搬迁或复制认证文件。

## 范围变更（2026-10-17）

用户决定停用 Claude Code，改用 DeepSeek API。首版活动选项变更为 Codex CLI 与 DeepSeek API；本节记录该变更，不改写原始评审记录。

- DeepSeek 使用应用固定的 HTTPS Chat Completions 请求；API Key 仅从 `DEEPSEEK_API_KEY` 进程环境读取，不落盘。
- 每次运行开始前展示外发数据类别、文件名称/摘要范围、无文件附件、无工具和按 token 计费，并由用户单独同意。暂停时授权仅保留给同一运行；运行终止、失败、取消或关闭窗口时撤销。
- 首版不开放 API 工具、文件访问、浏览或生成代码执行。受控代码执行仍由独立执行边界验收决定，DeepSeek 接入不会绕过该门。
- 当前实现尚未接入默认桌面工作流，也没有经过远端连接、账户额度或真实模型响应验证；有本地 Key 只表示配置存在，不能作为运行就绪证明。发布状态以 `docs/release/acceptance.md` 最新跟进为准。
