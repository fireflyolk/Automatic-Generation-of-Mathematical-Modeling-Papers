# Agent 运行过程侧栏设计规格

日期：2026-10-18
状态：待用户评审
范围：运行与审核页的工作流阶段进度、Agent 实时事件和阶段产物摘要

## 1. 目标与成功标准

在“运行与审核”页运行任务时，用户能够同时看到当前阶段、Agent 可观察到的执行过程、每个阶段的结果和已生成产物。事件从后台工作流产生后即时送到界面，不必等整轮完成才批量出现。

成功标准：

- 页面持续显示阶段状态、阶段进度和取消/继续操作。
- 时间线按发生顺序显示运行、阶段、Agent 请求、可见 Agent 消息、校验、产物和错误事件。
- 可展开查看完整的 Agent 可见消息；隐藏推理内容不作为普通事件显示。
- 阶段产物显示名称、类型、大小、审核状态和已有的产物访问入口，不复制产物正文到事件文本。
- 事件详情仅保存在当前应用会话的内存中，不写入运行数据库、检查点、项目日志或生成产物。
- 运行事件接收或渲染失败不能改变工作流结果。
- 事件不显示 API 密钥、认证头、完整提示词或题目/数据全文；密钥样式的内容在显示前脱敏。

## 2. 用户界面

保留现有“运行与审核”页面的导航、阶段进度和运行控制。页面主体改成可调宽度的双栏：左侧保留运行状态、阶段列表和操作；右侧新增“Agent 实时过程”侧栏，展示时间线、事件详情和阶段产物清单。用户可拖动分隔条调整宽度；可用宽度不足时侧栏折叠为可打开的面板，不让页面出现横向溢出。

时间线每条事件至少显示时间、阶段、事件类型和简明标题。可见 Agent 消息和较长事件内容放入可展开详情，便于查看完整内容而不挤占时间线。页面在用户位于底部时跟随新事件；用户滚动查看旧事件时保持当前位置，并提示有新事件。提供“全部 / 阶段 / Agent / 产物 / 错误”筛选，以及清空当前会话显示的操作。

每阶段的产物清单作为可展开区块显示文件名、类型、字节数和已有的审核结果；路径只显示本次运行目录内的相对路径。已存在的产物审核入口继续复用。侧栏不创建文件，也不新增单独的持久化产物数据库。

## 3. 事件模型与数据流

工作流和 Agent Provider 使用统一、只读的结构化运行事件，经后台 worker 的 Qt queued signal 传递给界面。UI 只消费经过字段白名单校验的展示模型，不直接格式化 Provider 原始 JSON、HTTP 响应或进程输出。

事件字段包括：运行标识、单调序号、发生时间、阶段、尝试次数、事件类型、简短标题、可选的可见消息详情和可选的产物摘要。事件类型包括：

- 运行开始、运行暂停、取消、失败、完成；
- 阶段开始、阶段进度、阶段完成；
- Agent 请求准备、已发送/等待、已收到响应、可见消息片段、受控失败；
- 校验开始、通过、未通过；
- 产物创建或审核完成。

工作流引擎在阶段切换、阶段状态变化、校验结果和产物提交时通知 observer。LiveWorkflowEngine 在请求边界通知 Provider 请求状态，并把 AgentAdapter 的安全事件映射成相同展示模型。UI 接收回调不作为工作流事务的一部分；回调异常只产生不含原始内容的当前会话通用界面提示，并丢弃该显示事件，不写入项目日志，不能回滚阶段产物、改写运行状态或吞掉真实工作流异常。

同一运行恢复时沿用应用内已有的内存时间线，并从当前阶段继续追加事件。新运行开始时显示新运行事件。关闭应用后，侧栏事件不恢复；重新打开项目仍可查看原有阶段记录、运行状态和产物审核数据。

## 4. Agent 显示边界

只显示 Agent 对外可见的消息，不显示标记为 reasoning、内部思维链或隐藏分析的内容。Codex 消息按安全协议产生时可增量显示；DeepSeek 当前使用非流式 HTTP 请求，显示“已发送 / 等待响应 / 已收到响应”，收到后将完整可见回复放入可展开详情，不显示逐 token 动画。

只有 Provider 在已批准能力范围内实际发出的工具事件，才可显示工具名、经脱敏的动作摘要、成功/失败状态及有限结果预览。禁止的工具事件显示为“已拦截并停止”，不得伪装成已执行。当前 Codex 适配器的生产路径在精确范围可信检查完成前会阻止自动运行；DeepSeek 不开放工具调用。因此，初版不能承诺展示真实命令、文件、浏览器或 MCP 操作。若将来授权并验收了这些能力，再由后续规格增加其事件。

完整提示词、完整输入内容、认证信息、HTTP 请求头、内部推理和未经筛选的原始工具输出不进入事件模型。Agent 可见消息显示前执行凭据样式脱敏；事件详情仅供本机当前会话查看，不写盘或外发。DeepSeek 费用与数据外发授权仍由现有运行前确认流程控制，增加侧栏不得扩展请求范围。

## 5. 限制、错误与资源上限

每条事件复用现有边界：文本 UTF-8 大小不超过 64 KiB，单次运行最多 2,048 条。达到上限时保留最新事件、阶段状态和产物清单，并在时间线显示已省略旧事件的提示。事件内容超长时在详情中明确标注截断，不静默丢弃。超时、取消、预检阻止、Provider 拒绝、响应解析失败和校验失败分别显示可理解的状态；原始 API Key、Authorization 头、未经处理的网络异常正文和堆栈不进入用户事件。

若 Provider 不支持流式响应，UI 必须明确显示等待状态；不得推断 token 进度。若事件格式未知、超出大小上限或运行标识不匹配，丢弃该事件并在当前会话显示不含事件内容的通用诊断，不写入项目日志，也不改变工作流结果。

## 6. 验收范围

实现后需要覆盖：

- 单元测试：事件字段校验、阶段/Provider 事件映射、密钥脱敏、超限与异常回调隔离。
- 工作流集成测试：Fake Provider 实时发出多个事件；确认阶段开始、Agent 等待/完成、校验和产物事件按序到达；确认回调异常不影响检查点和工作流结果。
- Provider 合同测试：Codex 可见文本增量被映射，reasoning 不显示，未知/越权工具事件变为阻止状态；DeepSeek 显示请求/等待/收到响应而不伪造流式输出。
- Qt 界面测试：运行中实时追加、详情展开、筛选、跟随滚动、窄窗口折叠、取消/继续控件仍可操作、事件上限提示及会话内存清理。
- 端到端验收：使用模拟 Provider 完成整条工作流并在侧栏看到阶段和产物；真实 Codex/DeepSeek 是否可运行仍由各自连接、授权与隔离验收门禁决定，侧栏功能通过不等同于 Provider 或完整工作流验收通过。

本规格不改变 Agent 工具权限、费用授权、代码执行隔离或 Word 生成规则。
