# Windows Sandbox 受控计算规格

日期：2026-10-18

## 问题

当前 `PythonRunner` 保存生成脚本后固定暂停。`LiveWorkflowEngine` 已向计算阶段传入已选 CSV、XLSX 和 DOCX 数据副本，但桌面应用没有可用的隔离 Python 执行后端，因此无法完成真实计算。

## 已验证的主机能力

探针记录位于 `[本机路径已省略]`。当前 Windows Sandbox 能启动 F 盘提供的 CPython 3.13.14；只读映射拒绝写入；独立输出映射可写；未映射的 F 盘哨兵文件不可读；`openpyxl` 3.1.5 与 `pypdf` 6.21.1 可在来宾中导入。探针配置关闭了网络。

## 设计

- 为每次计算创建新的 Windows Sandbox 会话。输入快照和只读 Python 运行时单独映射为只读目录；唯一可写映射是本次运行的临时输出目录。
- 来宾启动时先验证映射和配置，再以输入目录、输出目录两个参数执行 `30_src/generated.py`。关闭网络、剪贴板、打印机、音视频与 vGPU。使用 300 秒超时。Windows Sandbox 的最小内存配置是 2 GiB，因此来宾内存上限按 2 GiB 配置；若主机无法在该限制下启动，则 fail-closed。
- 主机只复制当前项目中经 SHA-256 复核的选定 CSV、XLSX、DOCX 数据文件。原始导入文件保持只读且不被修改。生成代码不能访问 Agent CLI/API 凭据，也不能通过网络访问外部服务。
- 运行时为 F 盘应用包内的只读 Python 3.13 x64 发行目录；不依赖未受控的 PATH Python。运行时包含应用声明的表格/DOCX 支持，以及锁定版本的 NumPy、pandas、SciPy、Matplotlib。
- 主机只接受代码计划声明的简单文件名和类型：CSV 写入本次 `40_results/calc-NNNN`，PNG 写入 `50_figures/calc-NNNN`。逐项检查文件名、数量、大小、CSV 表头/行数/数值、PNG 格式并计算哈希；验证后才登记为证据。日志只保留限长、脱敏后的状态，不保存原始输入内容。
- 用户取消、超时、沙盒启动失败、映射检查失败或输出检查失败时，终止沙盒并将计算阶段暂停/失败；绝不回退到宿主机直接执行。
- 在“运行与审核”中显示 Windows Sandbox 检测状态、计算运行状态和失败原因；只有可用的实时预检通过后才运行计算。

## 范围

只替换当前始终暂停的受控 Python 执行器，并为发行包提供隔离运行时。保留 Agent 选择、数据发送范围确认、项目目录、论文生成与人工审核边界。不会重新尝试 LPAC，不会把用户数据移出 F 盘，也不会在沙盒中开放网络。

## 验收

1. 单元测试覆盖沙盒配置、F 盘路径验证、输入快照哈希、输出清单/CSV/PNG 校验、超时、取消、启动失败及 fail-closed 行为。
2. Windows Sandbox 集成测试用合成 CSV/XLSX/DOCX 样例执行脚本，生成声明的 CSV/PNG；验证只读输入、独立输出、未映射主机路径不可访问、网络关闭，以及宿主原始文件哈希未变。
3. 发行包验收确认运行时与应用文件都位于 F 盘，并从实际桌面 EXE 跑完“代码生成→计算→结果验证”。真实 Agent/API 请求和数学正确性另行如实记录，不以模拟器代替。
4. 失败记录保存在 `[本机路径已省略]` 下，标明源码、发行 EXE、实时 API、沙盒和 Word 渲染各自的证据范围。
