# B078 长文论文与结构化图示扩展

**状态：** 用户已明确要求将软件目标提高到 40–50 页并增加公式、流程图和说明图；据此继续实施。
**适用范围：** 新建论文运行的默认内容规范、Agent 起草请求、结构化图示、Word 写入和质量报告。

## 1. 目标与边界

- 默认目标为 45 页，规划范围为 40–50 页；页面数只在真实 Word 渲染后报告为已知。
- 以足够的模型推导、公式解释、求解步骤、结果分析和附录支撑篇幅，不通过重复段落、空白页、无关内容或虚构结果凑页数。
- 建议约 12 个可编辑公式对象、至少 3 张结构化流程图和约 50,000 个正文字符。题目或证据不支持的项目应列为质量建议，不阻断工作流。
- Codex 与 DeepSeek 共用相同的分章协议。正文拆为最多 8 段；JSON 格式纠正时每段可额外重试一次，因此最多 16 次 Agent 请求。运行确认页说明额外请求可能增加服务用量，DeepSeek 按 token 计费。
- 流程图只接受有界节点/连线数据，由本机绘制；不接受模型提供的图片、SVG、代码或外部资源。图后必须有说明并提示人工核对。
- 用户自选 Word 模板继续控制版式并保持源文件不变；历史 1.0.0 运行仍可读取其规范记录。

## 2. 实现范围

1. 发布 `b078-competition-v1` 的 1.1.0 版本，记录 40–50 页、45 页目标、内容长度及公式/流程图建议值；保留 1.0.0 的规范哈希与读取能力。
2. 将论文起草拆为最多八段：摘要与重述、问题分析、假设与符号、模型推导第一段、模型推导补充、求解方法、结果与检验、结论与附录。每段采用共享 JSON 请求协议，结果仅在合并和全量校验后写入 Word。
3. 使用纯结构的流程图协议，限制节点数、连线数、标签长度和关系合法性；本地渲染为 PNG，并作为带说明的连续编号插图写入论文。
4. DOCX 质量报告新增正文字符数、流程图数量和 40–50 页目标状态；篇幅或图示不足产生明确提示，不单独触发暂停。
5. 运行确认页披露分章请求数、最多一次格式重试和 token 用量影响。读取 DeepSeek 模型目录中的输出上限，应用按模型支持值截顶至 16,384 tokens。标准版本、模板哈希、公式数、图示数和内容长度写入 `paper-manifest.json`。

## 3. 验收边界

- 默认规范用于 Codex 与 DeepSeek 的同一 provider-neutral 请求路径；分章内容在应用端合并后统一校验。
- 公式按可编辑 Word 数学对象输出；流程图作为本地生成图像输出，图题、说明和人工复核标记相邻。
- 图示缺少、内容量不足或真实页数未渲染均只能作为质量提示；文档包损坏、无效模板映射、未解析占位符或错误证据引用仍可阻断验收。
- 自动构建和结构检查不等同于真实 Agent 请求、真实 40–50 页 Word 渲染或最终模板视觉验收；报告必须分开陈述。
- Do not modify user-provided source material.
